# Gardener's Walk — receding-horizon conformant planning (Alpha vs. clingo)

The gardener walks a 30x30 garden (4 actions: N/S/E/W). ~10% of the cells are hedges
(walls): the gardener cannot pass them — walking into one is a harmless *bump* (he stays
put) — while frogs simply hop over them. The free space is guaranteed connected. Frogs are
*skittish*: each time step a frog hops one cell strictly toward the gardener's current
position (or stays if the gardener stands on it). The norm is the original Gardener MTN1,
conformant: **the gardener must never be on a cell that any frog could possibly occupy**,
over all frog behaviours, within the lookahead horizon h.

The execution loop is the papers' receding-horizon policy-fix loop: solve for a safe
h-step plan, execute the first action, observe the frogs' actual (random) hops, extend
the program by the 2+f observation facts (executed move, one `frogAt` per frog, one new
`step` fact) and re-solve. The danger cones re-anchor at the latest observation via
default negation (`superseded`), so the program grows strictly monotonically — no
retraction — and the active cone keeps constant depth h.

Why it separates the solvers: the frogs REACT to the gardener, so the danger closure
joins `playerAt` — eager grounding must instantiate |player-diamond| x |frog-cone| per
time step for every hypothetical position (measured 32x more ground rules than the
random-frog control), re-paid per shot (rebuilt) or pre-paid over the whole grid
(#external anchors, clingo MSS). Alpha's lazy grounding realises only the cone along the
one actual trajectory per branch.

## Layout

```
examples/walk/
├── gen_walk_instance.py     # seeded instances: random frog starts + connected 10% walls
├── walk_clingo.py           # clingo drivers: batch (fresh anchored window/shot) + mss (#external anchors)
├── instances/               # inst-W30-f<F>-s<seed>.spec (generated by copperbench setup.sh)
└── README.md
```

The Alpha driver is `GardenersWalkBenchmark` (alpha-cli-app examples): `live` keeps one
session across shots (grounder wake-up ingests the observation facts), `batch` rebuilds
per shot. Every shot's plan is verified by an independent BFS cone checker, and the
executed walk is checked capture-free. Encoding notes that matter for Alpha: all guards
are positive (`free`/`wall` fact joins — negated wall literals are ~100x slower), the
transition function is total (bump semantics — dead move branches thrash the solver), and
justification search must stay enabled in session mode.

Run one instance locally:

```
python3 gen_walk_instance.py 30 2 200 10 10 > /tmp/i.spec
java -cp alpha-cli-app/build/install/alpha-cli-app/lib/'*' \
     at.ac.tuwien.kr.alpha.app.examples.GardenersWalkBenchmark live 30 12 2 20 7 /tmp/i.spec
python3 walk_clingo.py batch 30 12 2 20 7 /tmp/i.spec
```
